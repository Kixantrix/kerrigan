# M3.1: Plan markdown parser (`src/plan-parser.ts`) (excerpt)

## Goal
Parse a project `plan.md` into a typed stage graph that downstream milestones
(M3.2 status derivation, M3.3 DAG canvas, M5.2 plan edits) consume. Pure:
string in, typed graph out.

## Behavior
- Extract stages from H2 / H3 headings. The heading text is the stage label;
  derive a stable `id` (slugified heading, deduped on collision). An H3 under
  an H2 is a child stage.
- Optional YAML frontmatter declares explicit stage dependencies:
  ```yaml
  ---
  dependencies:
    <stage-id>: [<stage-id>, ...]
  ---
  ```
- Handle malformed input with structured errors — never throw. Detect
  circular dependencies and unknown stage ids as structured errors.

## Notes
Keep the public type surface minimal and stable; M3.2/M3.3/M5.2 all key off
`PlanStageNode.id`, so design ids to be durable.
