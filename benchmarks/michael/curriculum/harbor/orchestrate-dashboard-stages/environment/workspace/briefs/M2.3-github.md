# M2.3: `src/github.ts` — Octokit wrapper + ETag polling + gh-auth shell-out (excerpt)

## Goal
Provide the dashboard's GitHub read path: an Octokit wrapper with ETag-aware
conditional polling and on-demand auth borrowed from `gh auth token`.
Pure data-access — no UI, no status derivation (that's M3.2).

## Hard constraints
- Zero credential persistence (AC-017). Resolve auth fresh on each call via the
  injected `gh auth token` shell-out; the token lives only in memory for the
  duration of a request. Never log or leak it.
- ETag cache short-circuits 304s: cache ETags per endpoint; send
  `If-None-Match`; treat 304 as "unchanged" (return cached data).
- Adaptive backoff (AC-014): on rate-limit pressure or an unreachable API,
  surface an "offline" result rather than throwing.

## Done when
1. A client factory obtains a token via the shell-out and calls the injected
   Octokit request function, holding the token only in memory.
2. Read helpers for the data the portfolio needs (open PRs, open issues, PR
   reviews) with ETag conditional requests.
3. Rate-limit/unreachable conditions return a typed offline result.

## Out of scope
Status derivation (M3.2), writes, the portfolio UI.
