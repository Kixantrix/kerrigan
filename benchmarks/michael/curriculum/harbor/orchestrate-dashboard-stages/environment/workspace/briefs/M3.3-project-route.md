# M3.3: Project detail route — data layer (`src/project-status.ts`) (excerpt)

> Dependencies (merged): M3.1 (`src/plan-parser.ts`) and M3.2
> (`src/status.ts`). Consume both as-is; do not edit them.

## Goal
The project-detail route renders a project's plan as a DAG whose nodes are
colored by AC-005 status. Its data layer parses the plan with
`parsePlanMarkdown`, sources PR/issue/review data via `github.ts`
(offline-tolerant) plus the blocks reader, derives statuses with
`deriveStatuses`, and returns them for rendering. Degrade gracefully when the
plan or GitHub is unavailable (no crash).

## Consume
- `deriveStatuses(graph, { prs, issues, blocks, reviewsByPr?, matcher? })` —
  the default matcher links a stage to work whose title contains the stage id;
  reuse it.
- `github.ts` (`GitHubResult<T>`) and the project's `repos` /
  `workingCopyPaths` from `projects.json`.

## Out of scope
`merged` status fidelity is limited by `github.ts` having no merged-PR read
path — color what the available data proves; do not widen `github.ts` here.
