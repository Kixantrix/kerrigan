# M5.1: `tools/kerrigan-mcp/` scaffold + `kerrigan.dispatch` tool

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 5.

> **Dependency:** `external:M4.2` (chat pane) — merged. Fully isolated to `tools/kerrigan-mcp/**` (a new top-level tool dir) — no overlap with the parallel M6.2/M7.2.

## Goal

Scaffold a **Model Context Protocol (MCP) server** at `tools/kerrigan-mcp/` (TypeScript, Node 22, stdio transport) and expose a first tool **`kerrigan.dispatch`** that wraps the existing dispatch flow (creates a GitHub issue from a briefing, assigned to the Copilot coding agent). Implements the server portion of **AC-010/AC-011**.

## Design

- **`tools/kerrigan-mcp/` (new):** a standalone TS MCP server using the official MCP TypeScript SDK (`@modelcontextprotocol/sdk`), registered via **stdio** transport. Standard layout: `package.json` (Node 22, `type: module`), `tsconfig.json`, `src/server.ts` (server bootstrap + tool registry), `src/tools/dispatch.ts`.
- **`kerrigan.dispatch` tool:** input schema `{ title: string; body: string (briefing markdown); labels?: string[]; repo?: string }`. It creates the issue and assigns the Copilot agent. **Reuse the repo's proven dispatch mechanics** rather than reinventing:
  - The existing Python dispatcher is [`tools/create_issues.py`](../../tools/create_issues.py); the single-issue path is [`tools/new-issue.ps1`](../../tools/new-issue.ps1). Either shell out to one of those, or replicate their exact behavior in TS: create via `gh issue create --title --body-file --label`, then assign Copilot via the **`@copilot`** handle (this is the working handle — bare `copilot` fails). Write the body as UTF-8 (no BOM).
  - Return the created issue number + URL.
- **Auth:** rely on `gh` for auth (it reads the user's token); do not handle tokens directly.
- **Tests:** an MCP integration test that starts the server, calls `kerrigan.dispatch` against a **fixture repo** (or a mocked `gh`), and asserts an issue is created with the expected title/labels/assignee. No real dispatch to this repo in CI.

## Hard constraints

- **Stay within `tools/kerrigan-mcp/**`.** Do not edit the dashboard app or other tools (the dashboard sidecar wiring that spawns this server is **M5.4**; the chat→MCP UI is later).
- Node 22, strict TS, ESM. No `any` in the tool schemas (use the SDK's zod-based input schemas).
- Never persist/log a token. The dispatch tool must not double-fire issue creation (the heredoc/double-create footgun — invoke `gh` exactly once per dispatch).
- Idempotency isn't required, but a failed `gh` call must return a structured MCP error, not crash the server.

## What "done" looks like

1. `tools/kerrigan-mcp/` is an installable Node 22 TS MCP server that registers over stdio and exposes `kerrigan.dispatch`.
2. Calling `kerrigan.dispatch` creates a GitHub issue (briefing body, labels) assigned to the Copilot agent and returns its number/URL.
3. **MCP integration test** against a fixture repo / mocked `gh` asserts the issue creation (title, labels, assignee, single `gh` invocation).
4. `tsc --noEmit` + lint clean for the package; `kerrigan check` still passes; the repo's smoke still passes (the new tool dir must not break root tooling).
