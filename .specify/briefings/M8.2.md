# M8.2: Inbox view + per-item actions

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 8.

> **Dependencies (both merged):** `external:M8.1` (`lib/inbox.ts`) and `external:M5.1` (MCP server, for the dispatch action). Owns the new `routes/inbox/**` + the `/inbox` route in `App.tsx` (no overlap with the parallel M5.2/M6.3).

## Goal

Build the **intervention inbox view**: a filterable list of everything needing attention across projects, with per-item actions. Implements **AC-012/AC-013**. The "process ≥10 items in ≤2 min" target is a **manual walkthrough metric** (SM-001/002), not an automated gate.

## Consume (as-is)

From [`lib/inbox.ts`](../../apps/kerrigan-dashboard/src/lib/inbox.ts) (M8.1): `InboxResult`, `InboxItem` (`kind: "block" | "capture-issue" | "review" | "attestation"`, `projectId`, `repo?`, `title`, `url?`, `createdAt`, `ageMs`), `BuildInboxOptions`, `createInboxGitHubClient`. **The aggregator already produces the typed, age-sorted feed** — this view renders it; don't re-aggregate. Mirror how `routes/portfolio/PortfolioView.tsx` consumes its lib (injectable client + offline tolerance + the route's existing data-loading pattern).

## Design

- **`routes/inbox/**` (new):** an inbox route that loads `InboxResult` (injectable inbox builder, default the real one; tests/E2E inject fixtures) and renders a **filterable** list (by **project**, **type/kind**, **age**). Offline-tolerant (render what's available + an offline indicator), graceful when empty.
- **Per-item actions** (assertable in Playwright):
  - **dispatch** — sends the item to the chat with a prefilled prompt (for now, since the chat pane isn't mounted into the route yet, wire this to a callback/stub that would call the MCP `kerrigan.dispatch`; keep it injectable so the E2E asserts the action fires with the right payload).
  - **close with reason** — closes the underlying issue/block (via `github.ts` / a callback) with a reason.
  - **snooze** — hides the item for a period (local state / `~/.kerrigan` persistence via injectable store).
- **Routing:** add the `/inbox` route to `App.tsx` (the router from M3.3) + a nav affordance from the header/portfolio. Keep the change additive.
- Design tokens only; amber `accent` for needs-attention counts (per `design-references.md`), red reserved for true blocks.

## Hard constraints

- Consume `inbox.ts` as-is; do not edit it or `github.ts`. The view only renders + acts.
- Touch `App.tsx` only to add the `/inbox` route (additive) — nothing else outside `routes/inbox/**`. (M5.2/M6.3 don't touch these — no collision.)
- Strict TS, no `any`. Injectable inbox builder + action callbacks (no real network in unit/component tests).
- The throughput target is a **manual** walkthrough metric — don't build an automated timer gate; the automated gate is the Playwright filter+action walkthrough.

## What "done" looks like

1. `/inbox` renders the unified feed (blocks + capture-issues + reviews + attestations), filterable by project/kind/age, offline-tolerant, age-sorted.
2. Per-item **dispatch / close-with-reason / snooze** are wired and assertable (injectable callbacks).
3. **Playwright E2E**: filter + dispatch + close walkthrough against fixture inbox data (automated gate). Component tests for the item renderers + filters.
4. `pnpm -C apps/kerrigan-dashboard test` + `lint` + `tsc --noEmit` clean. `kerrigan check` + smoke pass.
