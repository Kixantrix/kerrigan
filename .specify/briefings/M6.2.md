# M6.2: Branch-per-edit-session + draft PR open (`lib/plan-save.ts`)

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 6.

> **Dependencies (both merged):** `external:M6.1` (writable PlanEditor `onSave(markdown)`) and `external:M2.3` (`lib/github.ts`). Isolated to a NEW `lib/plan-save.ts` (+ test) — does NOT touch `ProjectView` (wiring the editor's `onSave` to this lib is a tiny later step), so it can't collide with the parallel M7.2.

## Goal

Add `lib/plan-save.ts`: the save mechanism behind the now-writable PlanEditor (M6.1). Each editing session opens a branch `plan-edits/<timestamp>-<short-sha>`; the first save commits + pushes and opens a **draft PR** via Octokit; subsequent saves push more commits to the same branch. Implements **AC-009**.

## Consume these (as-is)

- M6.1's `PlanEditor` exposes `onSave(markdown: string)` — this lib is what that callback drives (the wiring lives outside this slice). Design `plan-save.ts` as a **session object / functions** the route can call: e.g. `createPlanEditSession({ project, octokit/ghClient, filePath })` → `{ save(markdown): Promise<SaveResult> }`.
- [`lib/github.ts`](../../apps/kerrigan-dashboard/src/lib/github.ts) (`createGitHubClient`, `GitHubResult`) and/or Octokit (`@octokit/rest`, already a dep) for the PR open. [`lib/projects.ts`](../../apps/kerrigan-dashboard/src/lib/projects.ts) `Project` / `RepoRef` for the target repo + working-copy path.

## Design

- **Session lifecycle:** the first `save()` in a session derives a branch `plan-edits/<ISO-ish timestamp>-<short base sha>`, writes the markdown to the plan file, commits, pushes, and opens a **draft PR** (Octokit `pulls.create({ draft: true })`). Subsequent `save()` calls in the same session commit + push to the same branch (no new PR). Return a typed `SaveResult` (`{ branch, prNumber?, prUrl?, commitSha }`).
- **Injectable side-effects for testability:** the git operations (write file, commit, push) and the PR-open must be **injected** (a `GitOps` interface + a `PrOpener`), with defaults that use the real Tauri/git + Octokit. Tests inject fakes and assert the branch-name shape, the single-PR-on-first-save rule, and the same-branch-on-subsequent-saves rule against a **fixture repo** model.
- **Token via `gh auth token`** through the existing `github.ts` path; never persist/log it.
- Offline / push-failure → return a typed error `SaveResult` (the offline edit queue is **M6.3**, not here) — don't crash.

## Hard constraints

- **NEW file `lib/plan-save.ts` + its test ONLY.** Do **not** edit `ProjectView.tsx`, `PlanEditor.tsx`, or `github.ts`. (Wiring editor→save into the route is deferred so this slice stays conflict-free with M7.2's ProjectView changes.)
- No conflict detection / offline queue (that's **M6.3**).
- Strict TS, no `any`. Injectable side-effects (no real git/network in unit tests).
- Branch name must be stable/safe (`plan-edits/<timestamp>-<short-sha>`), no collisions within a session.
