# Briefing: MB-001a

## Objective

Implement the first MB-001 slice: a small, engine-neutral historical-evidence import contract that preserves original pilot payloads, checksums, conditions, attempts, and additive corrections using synthetic fixtures only.

## Acceptance criteria

- AC-MB-001: Given a synthetic JSON pilot containing a failed attempt, a cancellation/retry, an evaluator failure, and an additive stop-reason correction, import produces a versioned historical record without modifying source bytes or deleting/relabeling original payload fields, attempts, or denominators. Keep the original payload separate from additive corrections; preserve unknown fields. Reject a mismatched expected source SHA-256 explicitly. Reimport is deterministic and does not overwrite evidence. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_historical_import.py (tbd).
- AC-MB-001: Schema/version/type errors, inconsistent correction references, invalid source digests, and invalid inputs produce actionable errors, not a success-shaped fallback. Native/derived/unknown usage and historical conditions stay distinguishable; unavailable telemetry must not become zero. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_historical_import.py (tbd).
- AC-MB-003, partial: The imported envelope names task, target, condition, provenance, and historical status without assuming one inference runtime, host, or agent platform. This slice does not complete the full target/task/condition contracts. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_historical_import.py (tbd).
