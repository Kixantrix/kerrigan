# Briefing: MB-004

## Objective

Implement the offline durable trial ledger and cohort-aware comparison report so completion coverage, actual completion times, incomplete attempts, partial verification, and unknown costs cannot be misrepresented.

## Acceptance criteria

- AC-MB-004: Persist a validated frozen start before accepting trial events/finalization, with append-only evidence and explicit interrupted recovery. Reject duplicate/conflicting terminal writes, malformed references, and corrupt or truncated data explicitly; idempotent identical operations must not double-count or replay tools. Recover a started but unfinished trial as interrupted/ungraded, retaining prior event/artifact provenance and known elapsed coverage without inventing completion. A recovered start is not a fresh attempt. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_ledger_report.py (tbd).
- AC-MB-005: Report every started trial, first-attempt versus eventual verified completion, failed/ungraded/interrupted/evaluator-error coverage, stop reasons, independent verification and auxiliary partial assertion counts with explicit denominators. Retain all attempts and provenance; partial assertions are not task passes. Missing price/credits/power/time stay unknown or not-applicable, not zero. Zero-success ratios are undefined. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_ledger_report.py (tbd).
- AC-MB-003/005: Compare only explicit compatible cohorts with frozen task versions/digests, harness/configuration, declared budget/retry/cache policies, track, and controlled dimensions. Model/target changes are intended comparison factors, not a reason to pool incompatible harness/task/policy evidence. Practical-system host/observability differences must be disclosed; incompatible controlled-capability or historical/new-policy conditions must be refused or separately labeled. Avoid arbitrary automatic grouping or universal model rankings. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_ledger_report.py (tbd).
- AC-MB-005 timing: Emit per-task paired outcome/time rows, complete-versus-partial timing coverage, and separate setup/agent/verification/end-to-end phases. Completion times exist only for independently verified successful trials; unfinished attempts retain observed elapsed time. Both-success paired time differences must name their subset/denominator, never silently drop slower failures. All-attempt time/spend counts retries and failures. Incomplete telemetry must not yield complete aggregate totals or inferred superiority. — level: integration — environment: cloud-linux — test: tests/projects/michael_bench/test_ledger_report.py (tbd).
- AC-MB-001/003 preservation: Existing historical-import and manifest contracts stay compatible. Use validated bundle references and reuse existing engine evidence semantics without normalizing synthetic/historical records into new live successes. — level: integration — environment: cloud-linux — test: existing contract tests plus tests/projects/michael_bench/test_ledger_report.py.
