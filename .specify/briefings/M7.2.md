# M7.2: PR → stage particle binding + lifecycle states

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 7.

> **Dependencies (both merged):** `external:M7.1` (PrFlowOverlay engine) and `external:M3.2` (`lib/status.ts`). This slice owns the DAG-mount + ProjectView changes for the overlay; the parallel M5.1/M6.2 don't touch those files.

## Goal

Wire the show-stopper to reality: bind **PR lifecycle → particle flows** on the live DAG. Open PRs render an ongoing **streaming** particle along the PR→stage edge; **merged** PRs trigger an **absorbing** animation + a green node pulse; closed/abandoned PRs fade. Mount the `PrFlowOverlay` on the DAG canvas, computing real node screen-positions. Implements **AC-006/AC-007**.

## Design

- **`components/PrFlowOverlay/binding.ts` (new):** pure-ish mapping from `{ openPRs, mergedPRs (recent), stageStatuses, nodePositions }` → `PrFlow[]`. Open PR matched to a stage → a `streaming` flow from the PR's source point to the stage node; a PR that transitioned to merged → an `absorbing` flow (one-shot). Keep the lifecycle/transition logic here and unit-test it without React.
- **Mount on the DAG:** in `Dag.tsx` (or a thin wrapper in `ProjectView`), overlay `<PrFlowOverlay>` absolutely over the React Flow canvas (`pointer-events: none`), fed the computed `flows`. Recompute points on viewport/layout change.
- **Green pulse:** on `onAbsorbed(id)`, pulse the target `StageNode` green (AC-007). Add a minimal pulse signal to `StageNode.tsx` (e.g. a transient `pulsing` flag) — keep it within the merged status color.
- **PR source point:** the spec shows PRs flowing from a "PR card" into the node. If no PR-card UI exists yet, emit from a sensible source (e.g. a fixed inbound edge point or the PR's stage-edge origin) and note the follow-up; don't block on a PR-card component.
- **Respect reduced-motion** (the engine already does) and the AC-020 "one show-stopper" budget.

## Hard constraints

## Gap to document

`github.ts` (M2.3) exposes `listOpenPRs` only — **no merged-PR read path**. So "a PR transitioned to merged" can be inferred from a PR **leaving** the open set between polls (open last tick, absent now) → emit an `absorbing` flow for it. Document this; do **not** widen `github.ts` here.

## What "done" looks like

1. With fixture PR data, an open PR shows a streaming particle from its source into the matched stage node on the DAG; merging it (PR leaves the open set) triggers an absorb + the node pulses green.
2. **Vitest** unit tests for `binding.ts`: open→streaming; open→absorbing on leave-open-set; closed→fade; PR-to-stage match; no flow spam (transition-only).
3. **Playwright E2E** driving fixture PR states (open → streaming visible; merge → absorb + green pulse).
4. `pnpm -C apps/kerrigan-dashboard test` + `lint` + `tsc --noEmit` clean. `kerrigan check` + smoke pass.

## Out of scope

- A dedicated PR-card component as the particle source — use a sensible source point + note the follow-up.
- Widening `github.ts` with a merged-PR helper — infer from leave-open-set instead.
