# M5.2: `kerrigan.plan-update` MCP tool

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 5.

> **Dependency:** `external:M5.1` (MCP server) — merged. Isolated to `tools/kerrigan-mcp/**`. (M5.3 also touches this dir; it is NOT in this wave, so no collision.)

## Goal

Add a second MCP tool **`kerrigan.plan-update`** to the existing server: apply a **structured edit** (replace a stage, add a stage, edit a stage's dependencies) to a project's `plan.md`, commit it to a branch, and open a **draft PR**. Implements **AC-008** (chat-driven plan edits).

## Consume / extend (as-is)

- [`tools/kerrigan-mcp/src/server.ts`](../../tools/kerrigan-mcp/src/server.ts) — register the new tool here, mirroring how `dispatch` is registered.
- [`tools/kerrigan-mcp/src/tools/dispatch.ts`](../../tools/kerrigan-mcp/src/tools/dispatch.ts) — the established tool shape (zod input schema, `gh`-backed side effects, structured result). Follow it.

## Design

- **`tools/kerrigan-mcp/src/tools/plan-update.ts` (new):** input schema `{ repo, planPath, edit }` where `edit` is a discriminated union: `{ op: "replace-stage", stageId, markdown }` | `{ op: "add-stage", afterStageId?, markdown }` | `{ op: "edit-deps", stageId, dependencies: string[] }`. Apply the edit to the plan markdown (operate on the heading/section for `stageId`), commit to a new branch `plan-edits/<timestamp>-<short-sha>`, push, and open a draft PR via `gh` (or Octokit). Return `{ branch, prNumber, prUrl, diff? }`.
- Reuse the repo's dispatch footguns lessons: `gh` auth (no token handling), single invocation, UTF-8 no-BOM for any body files, `@copilot` handle if assigning.
- **Tests:** integration test against a fixture repo (or mocked `gh`/git) asserting the PR opens with the expected diff for each `op`.

## Hard constraints

- **Stay within `tools/kerrigan-mcp/**`.** Don't touch the dashboard or other tools.
- Strict TS, ESM, Node 22; zod input schema (no `any`). Structured MCP errors on failure, no crash.
- Don't reimplement stage parsing from scratch if a shared helper exists — but this tool is server-side (Node), so a self-contained markdown-section edit is fine; keep it robust (match the stage by its `## `/`### ` heading text/slug).
