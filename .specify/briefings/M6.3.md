# M6.3: Conflict detection + offline edit queue

Single-dispatch task from [`specs/projects/kerrigan-dashboard/tasks.md`](../../specs/projects/kerrigan-dashboard/tasks.md) Milestone 6.

> **Dependency:** `external:M6.2` (`lib/plan-save.ts`) — merged. Isolated to NEW `lib/plan-conflict.ts` + `lib/plan-queue.ts` (no overlap with the parallel M5.2/M8.2).

## Goal

Two guards around the plan-save flow (M6.2): (1) **conflict detection** — if the plan file is touched by an open PR from an `agent:go`-assigned issue, block the save and surface the conflict; (2) **offline edit queue** — serialize edits to `~/.kerrigan/queue/` when offline and replay on reconnect. Implements **AC-009/AC-015**.

From [`lib/plan-save.ts`](../../apps/kerrigan-dashboard/src/lib/plan-save.ts) (M6.2): `createPlanEditSession`, `PlanEditSession`, `SaveResult`, `GitOps`, `PrOpener`. From [`lib/github.ts`](../../apps/kerrigan-dashboard/src/lib/github.ts): `GitHubClient` (`listOpenPRs`, `listIssues`) + `GitHubResult`. ## Design

- **`lib/plan-conflict.ts` (new):** `detectPlanConflict({ ghClient, repo, planPath, openPRs })` → checks whether any **open PR from an `agent:go`-labeled issue** touches the plan file (match PR's changed files / linked issue label). Returns a typed `{ conflicted: boolean; pr?: {...} }`. Pure-ish over injected GitHub data; the save flow consults it and **blocks** on conflict, returning a `SaveResult` failure that names the conflicting PR (the inbox preview surfaces it — that wiring is M8/elsewhere; just return the structured conflict).
- **`lib/plan-queue.ts` (new):** an offline queue that serializes a pending edit (`{ markdown, planPath, timestamp }`) to `~/.kerrigan/queue/<id>.json` (injectable fs, default Tauri fs) when a save fails offline, and a `replayQueue(session)` that replays queued edits on reconnect (in order) and clears them on success. Typed results; never lose an edit; never double-apply.
- **Injectable side-effects + offline-tolerant.** Both consult `GitHubResult`'s `{ ok:false, offline }` path. Tests inject fakes; no real fs/network.

## Hard constraints

- **NEW files `lib/plan-conflict.ts` + `lib/plan-queue.ts` (+ tests) ONLY.** Do not edit `plan-save.ts`, `github.ts`, `ProjectView.tsx`. (Wiring these into the editor save flow is a small later step; keep isolated from M5.2/M8.2.)
- Strict TS, no `any`. Injectable fs/GitHub (no real fs/network in unit tests).
- Queue must be crash-safe (atomic-ish writes) and replay idempotently.

## What "done" looks like

1. `detectPlanConflict` flags a plan touched by an `agent:go` PR and returns the conflicting PR; clean when none.
2. `plan-queue` serializes an edit when offline and `replayQueue` replays + clears on reconnect, in order, idempotently.
3. **Vitest** (injected fakes): conflict cases; offline → enqueue → replay; no double-apply; offline `GitHubResult` handled.
4. `pnpm -C apps/kerrigan-dashboard test` + `lint` + `tsc --noEmit` clean. `kerrigan check` + smoke pass.
